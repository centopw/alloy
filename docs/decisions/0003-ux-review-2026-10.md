# 0003: UX review of the desktop shell (2026-10-18)

Status: accepted. Extends 0002 (Discord-style layout). Method: design-critique skill (Nielsen heuristics,
Gestalt, JTBD) applied to a screenshot of the running app on a real account (macOS, 1568x882, bridge rooms
and many DMs) plus the code.

**User goal:** read and answer conversations quickly, find a room, and see who/what a room is.
**Context:** desktop app (macOS/Windows/Linux), high-fidelity, live product. **Focus:** full review.

## 1. What works

- The three-column hierarchy (rail, room list, conversation) reads at a glance; the active room has a clear
  highlight and an unread badge that does not shift the row.
- Per-user colours, flat message rows and avatars everywhere keep long conversations scannable.
- The composer is one rounded container with an obvious primary action; the attach tooltip shows the layout
  can carry hints.
- Room avatars with initials fall back gracefully when no image exists.

## 2. Issues (and what was decided)

### High

1. **Sender shown as a raw Matrix ID** (`@facebookbot:matrix.hce.vn`). Heuristic 2 (match with the real
   world), 6. Cause: member profiles are not loaded for lazy-loaded rooms and the UI fell back to the ID.
   Decision: the engine fetches room members for each timeline; the UI resolves
   explicit name, then member name, then the ID localpart, and never the full ID. The ID stays available as
   the tooltip.
2. **Names and avatars are dead ends.** Heuristic 7 (efficiency), Fitts. Decision: a profile card (popover,
   bottom sheet on phones) opens from names, avatars, member rows and `matrix.to/#/@user` mention links, with
   Message, Mention and Copy ID.
3. **No way to see or edit a room.** Heuristic 3, 10. Decision: a Room info panel (name, topic, picture,
   alias, encryption, a private note stored as account data, and Media, Files, Links, Members tabs). Opened
   from the header title, the member strip and the room context menu.
4. **No right-click anywhere.** Heuristic 7. Decision: one context-menu primitive (right-click, long-press,
   Menu key) used on rooms (open, mark read, details, rename, picture, note, copy link/ID, leave), messages
   (reply, thread, react, copy, link, edit, delete), members and the user panel.

### Medium

5. **Inconsistent gutters** (12px header, 16px composer, 8+12px messages, mixed settings). Gestalt
   proximity/continuity: edges that do not line up read as noise. Decision: one rhythm in `layout.css`
   (`--alloy-layout-gutter` 16px, header height 48px, row inset 8px, row padding 12px, section gap 16px),
   applied to every panel, header, list, the composer and settings.
6. **Fixed-width side columns.** Heuristic 3 (user control). Decision: sidebar and right panels are
   resizable (drag, arrow keys, double-click resets), widths persisted and clamped.
7. **Icon buttons without explanations.** Heuristic 6 (recognition over recall). Decision: a global
   tooltip layer shows `aria-label`, `title` or `data-tooltip` (plus shortcut) for any interactive element on
   hover and keyboard focus; a static audit test fails the build when an icon-only button has no label.
8. **Directory dialog rows jump when a room name is long.** Gestalt similarity/alignment. Decision: grid rows
   with an ellipsised name column and a fixed right-aligned action column.

### Low

9. The rail's Home entry showed a letter and read as an account. It is now a Home icon.
10. The search hint said `Ctrl K` on macOS; it follows the platform (`Cmd K`).

## 3. Heuristic summary (after the fixes)

| Heuristic | Before | After |
|---|---|---|
| 2 Match with the real world | Fail (raw IDs) | Pass |
| 3 User control | Partial (fixed panels, no menus) | Pass |
| 4 Consistency | Partial (spacing) | Pass (shared rhythm) |
| 6 Recognition over recall | Partial (unlabelled icons) | Pass (tooltips + audit test) |
| 7 Flexibility and efficiency | Fail (no context menus) | Pass |

## 4. Consequences

- The engine gains `GetUserProfile`, `StartDirectMessage`, `SetRoomName/Topic/Avatar`, `GetRoomNote/SetRoomNote`,
  `MarkRoomRead` and `GetRoomMedia`; room notes are private account data `chat.alloy.room_note`.
- New UI primitives (context menu, tooltip layer, resize handle, profile card) are the only way to build
  those behaviours; components must not hand-roll popovers or `title`-only hints.
- Shared media/links are listed by paging history client-side so they also work in encrypted rooms.
- Not done: favourites/low-priority tags, per-room notification modes, pinned messages, a download action for
  files, desktop notifications.
